# 留言板（message-board）

一个带登录的留言板。**这是第一个"有后端"的项目** —— 数据不再存在你自己的浏览器里，而是存在一台一直在线的服务上，所以别人打开也能看到你留的话。

## 跟前四个项目的根本区别

| | 前面 4 个项目 | 这个项目 |
|---|---|---|
| 网页从哪来 | 硬盘上的一个文件，双击就开 | **后端程序现场生成的** |
| 数据存在哪 | 你自己浏览器的 localStorage | **云端数据库**（所有人共用一份） |
| 换台电脑打开 | 数据全没了 | **数据还在** |
| 别人能看到你写的吗 | 看不到 | **看得到** ← 这就是后端存在的意义 |

## 技术栈

| 部分 | 用什么 | 为什么 |
|---|---|---|
| 后端 | **Node.js**（+ Express） | 还是 JavaScript —— **不用学第二门语言**，只多学"它在服务端怎么跑" |
| 数据库 | **SQLite**（Node 自带） | 零安装。它就是一个文件，不需要单独装数据库软件、不需要买东西 |
| 查询语言 | **SQL**（只学 4 句） | 建表 / 插入 / 查询 / 删除。够用了，不会一次教完 |
| 前端 | 原生 HTML / CSS / JS | 跟前四个项目一套 |

**没有用到的**（故意的，它们是另一层噪音）：TypeScript、React/Vue、ORM、Docker、Nginx。

## 怎么跑起来

**这个项目跟前四个不一样：双击 `index.html` 是没用的，必须先让后端跑起来。**

```bash
cd D:\Code\projects\web\message-board
node server.js
```

看到这几行就是成功了：

```
----------------------------------------
后端已启动，正在监听 3000 端口
在浏览器打开：http://localhost:3000
----------------------------------------
```

然后浏览器打开 <http://localhost:3000>。

**这个终端窗口不能关** —— 关了就等于后端下班了，网页立刻打不开。这就是"后端"和"文件"最大的手感差异。

## 第 1 步的验收

| 访问 | 该看到什么 |
|---|---|
| <http://localhost:3000> | 一段网页，写着"但它不是一个文件" |
| <http://localhost:3000/api/hello> | 一段 JSON：`{"message":"后端活着","time":"..."}` |
| <http://localhost:3000/不存在的地址> | `没有这个地址：/不存在的地址`（这就是 404） |

另外，**每访问一次，运行后端的那个终端窗口里就会多打印一行** `收到请求：GET /api/hello`。那行字是后端在"接电话"的实况 —— 你在浏览器点的每一下，它那头都记着。

### 我实测时撞到的一个真实现象（值得知道）

浏览器地址栏里打中文路径，**浏览器会自动把它编码**成一串 `%E4%B8%8D...` 再发出去，所以你能正常看到 404。

但如果用命令行工具（如 curl）**直接发未编码的中文**，服务器会在**"解析请求"这一步就把请求拒掉**，回的是 **400 Bad Request** —— 请求根本没走到 `server.js` 的地址判断里（后台日志里也查不到这一条，是铁证）。

同一个"地址不存在"，400 和 404 的区别是**卡在哪一段**：

| 状态码 | 卡在哪一段 | 谁的责任 |
|---|---|---|
| `400` | Node 解析请求行 —— **还没进我的代码** | 发请求那一方，格式不合规 |
| `404` | 已经进了我的代码，是地址表里没有它 | 我的代码（或地址写错了） |

（这条判断法你在报错翻译官里已经学过一遍了 —— 现在是拿它解自己的题。）
